# Training

Сайт для прорешки тем по математическому анализу: **пределы, производные, интегралы**.
Оформление — «полужидкое стекло»: матовые стеклянные панели над медленно текущим цветным фоном на миллиметровке, светлая и тёмная тема.

- 3 тренажёра, 43 темы, 407 задач с проверкой ответа
- в каждой теме: теория → разбор примера → практика, подсказки и решения
- калькулятор с пошаговым решением, генератор задач трёх уровней, контрольная из 10 задач
- 6 PDF: шпаргалка и подробный разбор к каждой теме
- регистрация по почте с подтверждением через письмо, восстановление пароля, прогресс хранится в аккаунте
- без входа: 5 задач и калькулятор, материалы и PDF закрыты

## Структура

```
index.html          главная: вкладки «Тренажёры», «Материалы», «О сайте»
limits.html         тренажёр «Пределы»
derivatives.html    тренажёр «Производные»
integrals.html      тренажёр «Интегралы»
pdf/                шпаргалки и разборы
assets/glass.css    общий стиль «жидкое стекло» (токены, фон, панель навигации, кнопки)
assets/home.css     стили главной
assets/trainer.css  стеклянное оформление тренажёров (поверх их собственных стилей)
assets/site.js      тема, навигация, прогресс на главной, сброс прогресса
assets/auth.css     стили кнопки аккаунта, окна входа, плашки лимита и замков на материалах
assets/auth.js      аккаунт на всех страницах: вход и регистрация, прогресс в аккаунте, лимит 5 задач без входа, замки
backend/            бэкенд на Python (Flask): аккаунты по почте и прогресс; база — SQLite у себя, Postgres на хостинге
backend/app.py      сервер и адреса API: /api/register, /api/confirm, /api/login, /api/forgot, /api/reset, /api/progress и др.
backend/database.py база (SQLite или Postgres): пользователи, сессии, ссылки из писем, прогресс
backend/mailer.py   письма со ссылками (подтверждение почты, смена пароля) через Brevo или SMTP
backend/config.py   настройки из переменных окружения: база, адреса, почта, разрешённые сайты (CORS)
backend/.env.example образец файла backend/.env с паролем от почты (сам .env в git не попадает)
backend/requirements.txt  зависимости Python (Flask, gunicorn для хостинга, psycopg для Postgres)
.vercelignore       что не выкладывать на Vercel (папку backend/)
vercel.json         сайт на Vercel собирается как статический, без пресета Flask
```

Вставки сайта в файлы тренажёров помечены комментариями `<!-- Training: … -->` и `/* Training: … */`. Логика задач не менялась: тренажёр только сообщает `assets/auth.js` о сохранении прогресса (`window.TrainerBridge`).

## Запуск

Сборка не нужна. Локально:

```bash
python3 -m http.server 8000
```

и открыть http://localhost:8000.

### Бэкенд (аккаунты и прогресс)

Нужен Python 3. В отдельном терминале из корня проекта:

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на macOS и Linux: source .venv/bin/activate
pip install -r backend/requirements.txt
python backend/app.py
```

Сервер запустится на http://127.0.0.1:5000, база `backend/training.db` создастся сама и в git не попадает.
Аккаунты, лимит и замки включаются, когда сайт открыт на localhost.

**Письма.** Пока почта не настроена, письма не отправляются, а ссылки (подтверждение почты, смена пароля)
печатаются в терминал, где запущен сервер: открой ссылку в браузере. Чтобы письма уходили по-настоящему,
скопируй `backend/.env.example` в `backend/.env` и впиши ключ Brevo или данные SMTP-сервера.

**GitHub Pages.** Пока бэкенд не выложен на хостинг, на сайте всё работает как раньше: без аккаунтов,
лимита и замков. Как выложить — в разделе «Деплой» ниже.

Лимит и замки работают в браузере, поэтому опытный пользователь может их обойти, а PDF из папки `pdf/`
лежат в открытом репозитории. Для настоящей защиты PDF нужно убрать из репозитория и отдавать через бэкенд только вошедшим.

## Деплой: сайт на Vercel, бэкенд на Render

Бесплатный Render стирает файлы при каждом перезапуске и засыпании (после 15 минут без запросов)
и не даёт отправлять почту через SMTP. Поэтому на хостинге база — Postgres на [Neon](https://neon.com),
а письма уходят через HTTP API [Brevo](https://www.brevo.com). Код сам выбирает нужный вариант по переменным окружения.

1. **База — Neon.** Создать проект и скопировать строку подключения вида
   `postgresql://user:password@ep-....neon.tech/neondb?sslmode=require`. Таблицы сервер создаст сам.
2. **Письма — Brevo (необязательно).** В настройках создать API-ключ (SMTP & API → API Keys) и подтвердить
   адрес отправителя (Senders). Без подтверждённого отправителя Brevo письма не отправит.
   Если почту не подключать, на хостинге регистрация сразу открывает аккаунт без подтверждения почты,
   а «Забыл пароль?» скрыт. Подключишь Brevo — подтверждение и восстановление пароля включатся сами.
3. **Бэкенд — Render.** Проще всего через Blueprint: New → Blueprint → этот репозиторий.
   Render прочитает `render.yaml` (корень `backend`, сборка, запуск gunicorn, проверка `/api/health`)
   и спросит значения переменных. Вручную (New → Web Service) настройки те же:
   - Root Directory: `backend`
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `gunicorn app:app --workers 2 --timeout 60`
   - Health Check Path: `/api/health`
   - Environment:

     | Переменная | Значение |
     |---|---|
     | `DATABASE_URL` | строка подключения из Neon |
     | `BREVO_API_KEY` | ключ из Brevo (если подключаешь почту) |
     | `MAIL_FROM` | подтверждённый в Brevo адрес отправителя (если подключаешь почту) |
     | `API_URL` | адрес сервиса на Render, например `https://training-api.onrender.com` |
     | `SITE_URL` | адрес сайта, по умолчанию `https://training-theta-eight.vercel.app`; ему доступ к API открыт автоматически |
     | `ALLOWED_ORIGINS` | необязательно: другие адреса сайта через запятую |
     | `DEBUG` | `0` |

     Если `API_URL` или `SITE_URL` не заданы, на Render берутся адрес самого сервиса и адрес сайта на Vercel.

     Проверка: `https://<адрес-на-render>/api/health` (или просто главный адрес сервиса) отвечает JSON
     с `"ok": true`. В нём же видно, какая база (`postgres` — правильно, `sqlite` — не задан `DATABASE_URL`)
     и включена ли почта (`brevo`; `off` — не задан `BREVO_API_KEY`, регистрация без подтверждения почты).
4. **Сайт — Vercel** → Add New → Project → тот же репозиторий, Root Directory `./`.
   При импорте Vercel видит Flask в `backend/` и предлагает пресет Flask. Это не страшно:
   `vercel.json` (`"framework": null`) всё равно собирает сайт как статический (Other).
   Build Command и Output Directory не заполнять. Папку `backend/` Vercel не выкладывает (`.vercelignore`).
   Для сайта нужен **один** проект Vercel.
5. Вписать адрес Render в `PRODUCTION_API_URL` в `assets/auth.js`, закоммитить и запушить —
   Vercel и Render пересоберутся сами.

### Если Vercel показывает «404 DEPLOYMENT_NOT_FOUND»

Сборка с ошибкой `FLASK_ENTRYPOINT_NOT_FOUND` означает, что проект собирается с пресетом Flask.
Нужен `vercel.json` из репозитория (он ставит пресет Other) — сделай Redeploy последнего коммита.

Это значит, что у проекта, к которому привязан адрес, нет ни одного успешного деплоя
(проект пустой, удалён, или каждая сборка падает). Код сайта тут ни при чём.

1. В Vercel открой каждый проект, подключённый к репозиторию, и посмотри Settings → Domains:
   там видно, какому проекту принадлежит адрес.
2. Рабочий проект — тот, у которого последний деплой с ветки `main` зелёный (Deployments → Ready).
   Его адрес и есть адрес сайта.
3. Чтобы сайт открывался по старому адресу: удали адрес в пустом проекте (Settings → Domains → Remove)
   и добавь его в рабочий (Add → `имя.vercel.app`).
4. Лишние проекты удали (Settings → General → Delete Project): бэкенд живёт на Render,
   отдельный проект Vercel для папки `backend/` не нужен, и его сборка будет падать на каждом коммите.

Бесплатный Render засыпает без запросов, поэтому первый запрос после перерыва может идти около минуты.
